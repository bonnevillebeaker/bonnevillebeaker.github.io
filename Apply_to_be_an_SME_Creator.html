Our aim

Make scientific ideas understandable, interactive, and testable.

Science Made Easy brings explanations and hands-on learning into one shared space. An SME contribution should help a learner understand a scientific principle, connect it to the real world, and, when an interactive tool is useful, demonstrate that principle for themselves.

Rules of submission

Eligibility, verification, and technical requirements

All SME submissions must meet every requirement below before they will be reviewed.

  1. Graduate-level scientific credentials are required. Work will be accepted only from current graduate students or graduates holding a master’s or doctoral degree. Current graduate students must provide an official laboratory webpage that verifies their current status. Master’s and doctoral graduates must provide an electronically accessible thesis or dissertation that verifies the degree.
  2. A mentor referral is required. Every submission must include written confirmation from a mentor with an established, verifiable role in the relevant scientific community. The mentor must state that they reviewed the submitted work, confirmed that it functions as described, and found no malicious or concealed behavior.
  3. Only approved file types will be accepted. A submission may contain only .html, .css, .js, .txt, .csv, and ordinary static image files. Executables, installers, documents, archives within archives, and all other file types will be rejected.
  4. The submission must be completely self-contained. Articles and tools may not link to, load, embed, or request outside resources. This includes external webpages, APIs, CDNs, hosted libraries, fonts, scripts, stylesheets, images, data files, analytics, and tracking services. Scientific sources may be listed as plain-text citations, but not as active external links.
  5. Acceptance and publication are not guaranteed. Submission to the SME Creator program does not promise review, acceptance, publication, continued hosting, or placement within any specific SME section.
  6. Participation is voluntary and uncompensated. Participation is at will. There is no promise of payment, royalties, employment, sponsorship, reimbursement, or compensation of any kind.
  7. JavaScript must use the GNU GPL v3.0 license. Every submitted .js file must be original source code distributed under the GNU General Public License version 3.0. Include a plain-text copy of the GPL v3.0 license in the ZIP package and identify the license in README.txt.
  8. Original work and lawful assets are required. Scripts and written material must be original. AI may assist with development, writing, or design, but the creator remains responsible for the submission and the mentor must verify that the final tool functions correctly and is not malicious. Do not submit copyrighted, trademarked, plagiarized, or otherwise unauthorized material.
  9. Include a recognizable project logo. Standard SME practice is to include a fun, professional logo or mascot that users can associate with the tool, similar to the Smart Turtle logo. The logo may be AI generated, but it must look professional and the creator must have the right to use and publish it.
  10. Submissions may be modified for consistency. The Bonneville Beaker may propose or make scientific, editorial, accessibility, security, interface, and styling changes so a contribution fits the overall style and feel of the site. All proposed modifications will be reviewed with the submitter, and the final modified version will not be published until the submitter verifies and approves it.

Clarification: The no-external-links rule applies to the submitted article and tool. Your application email may include the credential-verification link, mentor information, and a view-only link used to deliver the ZIP file.

What we are looking for

Two kinds of SME contributions

01

Interactive science tools

Create a browser-based JavaScript tool that teaches or demonstrates a scientific principle.

  • The tool must be submitted with a companion article for the SME Topics menu.
  • The article should explain the science, refer directly to the tool, and guide the learner through activities or examples.
  • The learner should be able to change inputs, observe results, and use the tool to demonstrate the principles discussed in the article.
  • The tool should work in a modern browser without requiring installation.
02

Discussion-based topics

Submit an article exploring a high-level scientific concept that would not be meaningfully improved by adding an interactive tool.

  • Build the discussion around a clear scientific question, concept, controversy, or framework.
  • Define technical terms and write for an interested non-specialist audience.
  • Use reliable sources and distinguish established evidence from interpretation or speculation.
  • Include prompts, examples, or thought experiments that encourage active learning.

The SME process

From idea to published module

  1. Propose.Email a concise description of your topic, intended audience, learning goals, and the information needed to verify your graduate-level eligibility.
  2. Obtain a referral.Ask a qualified mentor to review the finished work and provide written confirmation that it functions as described and contains no malicious or concealed behavior.
  3. Submit.Email a view-only share link to a ZIP package containing the complete, self-contained article or tool and only the approved file types.
  4. Review.Submissions are evaluated for scientific accuracy, clarity, usability, accessibility, originality, licensing, rights, and security. Review does not guarantee acceptance or publication.
  5. Revise together.The Bonneville Beaker may adjust scientific wording, accessibility, security, interface details, and visual styling. Every modification will be reviewed with the submitter before final publication.
  6. Publish.Approved articles may appear under Topics, and approved interactive modules may also appear under Tools. Publication remains at the discretion of The Bonneville Beaker.

Package requirements

What to include in your ZIP file

your-topic-name/
  README.txt
  LICENSE.txt    # GNU GPL v3.0
  article.html
  article.css
  tool.html      # interactive submissions
  tool.css       # interactive submissions
  tool.js        # interactive submissions
  assets/
    images-and-data-files
  • Include every local .html, .css, and .js file needed for the article and tool.
  • Place only ordinary static image files and any approved .csv data files in an assets folder.
  • In README.txt, give the title, creator name, intended audience, learning objectives, file entry points, plain-text scientific references, licenses, AI-assistance disclosure, asset sources, and setup notes.
  • Include LICENSE.txt containing the GNU GPL v3.0 license, and identify every submitted .js file as GPL v3.0 licensed source code.
  • Include a professional project logo or mascot as an ordinary static image file. The logo may be AI generated, but it must be original or lawfully licensed for this use.
  • Use relative file paths so the submission works when opened from its own folder with internet access disabled.
  • Bundle every permitted dependency locally. Do not use external links, CDNs, APIs, hosted fonts, remote images, remote data, or network requests.
  • Do not include secrets, API keys, passwords, personal learner data, analytics, advertising, or tracking scripts.

Security rules

Keep submissions reviewable and safe

Because JavaScript is active code, every submission will be treated as untrusted until it has been reviewed. To make review safer:

  • Do not attach the ZIP directly to Gmail. Upload it to Google Drive or a public GitHub repository and email a view-only link.
  • Do not password-protect or encrypt the archive.
  • Do not include executables, installers, shell scripts, browser extensions, Office files, macros, hidden binaries, symbolic links, or nested archives.
  • Do not minify or obfuscate code. The submitted source must be readable and original.
  • Do not include copyrighted, trademarked, plagiarized, or unauthorized code, text, images, logos, data, or other assets.
  • Do not include external URLs or network requests. The article and tool must function locally with internet access disabled.
  • Do not use code that reads unrelated local files, accesses the clipboard without a user action, performs cryptocurrency mining, downloads additional code, or attempts to evade browser security controls.

Accepted file types only: .html, .css, .js, .txt, .csv, and ordinary static image files. No other formats will be reviewed.
